1) MyPoolExecutor потенциально выигрывает в производительности у стандартного ThreadPoolExecutor благодаря распределению
задач по нескольким очередям (round robin), что может снизить блокировку и улучшить использование потоков,
особенно при различном времени выполнения задач. Однако, использование нескольких очередей добавляет оверхед,
и выигрыш зависит от характеристик задач. Стандартный ThreadPoolExecutor проще и предпочтительнее, если не требуется
особого контроля за очередями и не обнаружено проблем с блокировкой.
2) Мини исследование:
   - corePoolSize: если слишком мало - то недостаточное использование ресурсов, низкая пропускная способность;
если оно слишком велико - то явный выгрыш в призводительности уменьшается - из-за затрат на переключение контекста.
   - maxPoolSize: если мало - очередь перепоняется, задачи могут отклоняться;
если много - деградация производительности из-за переключения контекста.
   - BlockingQueue: маленький размер - задачи отклоняются, высокая нагрузка на систему при создании потоков;
Большой размер - Высокая задержка, возможна перегрузка памяти.
   - keepAliveTime: Слишком короткое: Постоянное создание/уничтожение потоков, увеличение задержки.
Слишком длинное: Занимает ресурсы (память) в течение длительного времени.
3) В MyPoolExecutor задачи распределяются между несколькими очередями по принципу Round Robin. 
Каждой задаче поочередно назначается следующая очередь в циклическом порядке. Это обеспечивает более равномерную 
загрузку всех очередей и потенциально снижает блокировки по сравнению с использованием одной общей очереди.
